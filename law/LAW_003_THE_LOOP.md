## Why this law exists

This estate could answer and it could not persist. Everything AROUND an agent
was built — a REPL, a door, a glass, a spine, an MCP surface, streams,
matrices, provers — and nothing in it ever tried a thing a second time on its
own. The operator, 2026-09-17: *"nothing that is actually 'looping' or
'Running' like an agent would, its just these sloppy REPL cycles."*

The cause was not discipline. It was written in the code and in the law. The
flow engine refuses a cycle BY NAME — "cycle or unreachable node" — and
unrolls reflection into fixed passes. The coder's loop is that unrolling: one
attempt, one repair, then a gate. Retries answer an error and never a verdict,
which is right and which also means a FAIL can never be re-attempted. LAW 7
says caps on loops and no indefinite tickers. Together they describe a council
that ANSWERS, not an agent that WORKS.

And the prohibition shaped the estate's growth. A transport, a surface, a
prover is provable in one sitting; a loop is not provable unless it is allowed
to run, which the law forbade. So every sitting the lawful, provable thing to
build was one more thing around the loop. Months of that is not sloppiness; it
is an incentive doing exactly what it was set to do.

The opposite of an unbounded loop is not NO loop. It is a loop with a ceiling
and a stop condition a machine can check.

## THE LAW

1. **A LOOP IS LAWFUL.** A node may be returned to. The refusal of every cycle
   becomes the refusal of every UNBOUNDED cycle.

2. **THREE BOUNDS, ALL THREE, OR IT IS NOT A LOOP.**
   a. **A declared ceiling** — the greatest number of passes the returned-to
      node may take, inside the run's own budget. Declared in the spec, where
      a reader meets it, never inferred at run time.
   b. **A stop condition A MACHINE CHECKS** — a check over evidence the
      machine itself emitted. Never a model's account of its own work, and
      never prose: a seat can write the word PASS without anything having run,
      which is the laundering this estate closed on 2026-09-12 and does not
      reopen here.
   c. **EVERY PASS IN THE RECORD**, with its receipt, the failed ones
      included. A loop that hides its attempts is a loop nobody can audit, and
      an unauditable loop is worth less than no loop at all.

3. **THE GATE STANDS AT THE END.** A loop does not stop to ask permission to
   try again; it stops to ask permission to LAND. Nothing reaches the estate,
   the record, a remote or a person without the operator's hand (LAW 6, RULE
   6). Autonomy is inside the loop; the gate is outside it.

4. **A RETRY ANSWERS AN ERROR; A PASS ANSWERS A VERDICT.** A loop re-does the
   WORK after a FAIL, with the failure written down beside it. It never
   re-scores an answer it already has until the score agrees. The first is
   persistence; the second is laundering, and they are told apart by whether
   the work ran again.

5. **WHAT REFUSES BY NAME.** A back-edge with no ceiling. A loop with no
   machine-checked stop. A stop condition that reads prose. A loop that writes
   outside its jail. Each is refused when the spec is SAVED, not discovered
   when it runs — the engine's own habit, and the reason a refusal is cheap.

6. **BOUNDED EVERYTHING IS NOT REPEALED** (LAW 7). It is restated: bounded as
   a NUMBER rather than as a prohibition. The number is in the record, where
   anyone can count it, which is the stronger form of the same law.

## What this does not change

`can_approve: false` everywhere. One seat executes tools; one engine writes a
world. The jail. The law gate before any model reads a word. Testimony is
never fact (LAW 5). Nothing is edited while a sitting is open (SITTING LAW 5).
A loop makes the estate persistent at a task; it does not make it sovereign
over one.
