# Skill: Edit a File in the Ground

- **Action Keyword:** ground_edit
- **Description:** Replaces ONE exact passage in a file that is already in the ground itself — source in manjuel/ or atlas/line/, a test, a doc — on a LINE OF WORK, so a large source file can be changed without rewriting it whole. The passage must appear exactly once; an anchor that matches twice is refused with the count rather than guessed at. Refused by name, with nothing written: while the file's repository stands on main or master (open a line first with git_branch new through the door), a secret or .env, client data, worlds/, any .git/, law/, the governing files (CLAUDE.md, .gitignore, agents/, skills/, pipelines.md, commands.md, index_roots.txt), the record and the runtime stores, the proof stamps under tests/, BUILDMAP.md, binaries and projects/. The file's line endings are kept (a MIXED file is refused), and a .py that after the edit would not parse, or would import the network, call eval/exec/__import__, reach importlib or pass shell=True, is refused — the same check edit_file, write_file and the coder's own landing make. The reply says which line changed; the edit is unsaved until git_commit lands it on the line. Use for "edit manjuel/x.py", "change that function in the source", "fix the line in tests/". edit_file is the workspace's door, for scratch.
- **Parameters Needed:** <filepath>The file's path relative to the ground, e.g. manjuel/intent.py</filepath> <content>Two marked sections: a line `@@ OLD`, then the exact text already in the file, then a line `@@ NEW`, then what replaces it. Quote the old text exactly, whitespace and all.</content>
- **Path Args:** filepath -> ground
- **Says:** edit the source file, edit in the ground, change the source file, patch the source
